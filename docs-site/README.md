# docs-site

The public documentation site, at <https://docs.sandrpod.com>.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # → .vitepress/dist
```

## The two audiences

Every page is written for a person and fetchable by an agent. The build emits, in
addition to the HTML:

| Output | What it is |
|---|---|
| `/<page>.md` | the Markdown the page was generated from, at the page's URL |
| `/llms.txt` | the index, with one line per page and a `.md` link |
| `/llms-full.txt` | every page concatenated, for a single fetch |

Two buttons on every page come from `.vitepress/theme/CopyForLLM.vue`: **Copy for
LLM** puts the page on the clipboard with a source header, **View as Markdown**
opens the `.md` twin.

`buildEnd` in `.vitepress/config.mts` writes all of it (`llm.ts`); nothing is
generated by hand.

## Language switching

`LangSwitch.vue` replaces VitePress's built-in menu, which maps
`/zh/quickstart` ↔ `/quickstart` and drops the `#anchor` while doing it. Ours keeps
`location.hash` at click time, so a reader on `/zh/e2b#密钥` lands on
`/e2b#密钥` rather than at the top of the English page.

Anchors are per-language: a heading whose slug differs (`## 鉴权` vs
`## Authentication`) has no counterpart, and the browser falls back to the top of
the page. Headings that share a slug (`#api`, `#cli`) work in both directions.

## Deploying

The site is served by Caddy from a directory on the application host — no
third-party build service, so a docs change is two commands:

```bash
# on the host
cd /opt/sandrpod-oss && git pull
cd docs-site && npm install --silent && npx vitepress build
sudo rsync -a --delete .vitepress/dist/ /var/www/docs/
```

`/etc/caddy/docs.caddy` serves that directory, with `.md` forced to
`text/plain` so a tool fetches it instead of a browser downloading it, and
`try_files` giving clean URLs.
