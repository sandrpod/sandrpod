# 控制台故障排查

## "已达到套餐上限"

工作区持有的并发沙箱已经等于套餐允许的数量 —— **包括已停止的**。删掉不用的沙箱；删除
释放名额，停止不释放。见 [限额](/zh/console-limits)。

## "余额不足"

钱包为零或负。充值，或者删掉正在跑的东西。邮件和横幅会先出现：拒绝是最后一步，不是第一
个提醒。

## 付了钱，额度没到

按顺序查三件事：

1. **计费里的订单状态。** `pending` 意味着服务商还没通知我们；会话过期后订单作废，不算
   扣款。
2. **服务商后台。** 如果它显示已完成，说明 webhook 没到 —— 这是部署问题，不是钱的问题。
   支持可以核对。
3. **金额。** 充值按你实际支付的金额换算成分。

卡支付失败会留下 `pending` 订单，**不会发邮件**。那是服务商的契约，不是 bug：一次性
订单没有失败 webhook。

## 终端连上了但一片空白

沙箱在跑，但它的 worker 没有连在服务这个请求的实例上 —— 这种情况下控制台会显示
`tunnel not available`。刷新一次；如果还在，说明 worker 掉了。看 Worker 页，状态
`OFFLINE`。

## 沙箱一直"创建中"

创建没有到达 worker。打开沙箱菜单里的 **Job** 看原因。`no available poder found` 表示
机队放不下它：检查 **Worker**（在线吗？到容器上限了吗？地域对吗？）。

引擎会为丢失的投递重试大约一分钟；如果还停在创建中，job 行里有原因。

## API 密钥在 CLI 里好用，在 E2B SDK 里不行

SDK 只认 `e2b_<hex>` 且在客户端校验。用 `format: e2b` 签一把 —— 见
[API 密钥](/zh/console-keys)。

## 邮件一直没来

验证和重置链接来自部署的邮件通道。先看垃圾邮件，再找支持：发信域名配置错误是最常见
原因，而且它一次影响所有收件人。

## 该看哪里

| 问题 | 去哪看 |
|---|---|
| 平台健康吗 | 部署机的 `/healthz` |
| 这个工作区在干什么 | 工作区 → 用量 |
| 谁做了什么 | 审计 |
| 这次创建为什么被拒 | 沙箱菜单 → Job |
| worker 都在线吗 | Worker |
